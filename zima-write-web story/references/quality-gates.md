# 正文写作质量门

以下完整开写与四阶段门用于正文批次。只润色/审查已有文本时，先按 [handoff-contract.md](handoff-contract.md) 记录范围与版本，检查本次适用的表达/事实门；不以无 active 包或缺未执行角色报告判失败，也不得将限定任务通过冒称整批接收或全书完结。

## 交接与读取

- 当前项目、用户总范围、章节范围和逐章恢复状态一致；源 skill 不因缺本书专属表单而被误报安装不全。
- 当前入口只指向一个有效 `active` 包；元数据、规划/事实/风格版本及验收证据符合 [handoff-contract.md](handoff-contract.md)。
- 当前入口、项目进度/逐章恢复、已接受事实基线一致；没有仅日志更新、总进度仍停在旧批次的情况。激活下一包或收尾前已回读核对，发现不一致先修正再验收。
- 包硬点承接对应章纲来源条目；缺本批硬连续事实已定向补证，未解决的依赖未开写。
- 材料按内容和阶段生成/读取，不适用有 `N/A` 理由；零正文首批不要求上批报告。
- 普通批次读最小工作集，缺项或偏移升级回读；用户全书审查要求不被降成局部检查。

## 正文与表达保护

- 每章服务已审目标，因果、人物选择及代价可感知；授权内可设计动作、对白和细节，不擅改关键动机或规则。
- 必要冲突、推理、动作和高潮有完整过程，不是剧情摘要；不按固定字数凑章，也不为“简洁”删掉必要容量。
- 章末符合本章功能和后续规划；全书终章可收束，不强造钩子或机械要求钩子类型轮换。
- writer 已使用小说表达模块的正向初稿指引；polisher 在初稿后使用润色指引；本书风格与内容约束优先。
- 润色没有机械禁用固定句式/标点，没有因“重复”一词就删掉有意复现、迟疑、仪式或情绪递进。
- 技法有实际落点；已有技法包复用，缺技法、新类型或同类问题复发才更新路由。

## 连续性与事实

- 时间线、动作/道具、伤势、资源、关系和认知连续。
- 重复动作区分状态矛盾、无增量冗余、有意重复，并说明依据；有意重复保留功能。
- 角色信息可来自前文、初始设定、身份自带知识或有效获得路径；异常知情若为伏笔，有可感知提示及回收安排。
- 叙述视角依本书配置。熟悉地点、已知身份和允许的全知叙述可直接命名；限制视角中角色未知信息的确定判断才检查证据链，不能统一要求所有场景先观察再命名。
- 新增事实与状态先是候选，经审查、修复复审和主 agent 接受后才写入正式基线；缺证据不靠润色补造过去事实。

## 审查与恢复

- 普通 checker 有“执行包硬点 → 正文证据”表及正文版本；缺项/偏移时有回读规划证据。checker 检查事实与对应，不新增文笔裁判职责。
- 红色问题修复后有受影响范围复审；黄色项有处理决定，未结阻塞清楚。
- 正文变化使相关旧报告失效，规划或已接受事实变化使依赖包失效；新版本不能借用旧通过结论。
- 逐章阶段、正文版本、报告、未结项和下一动作可恢复；未受影响且已通过章节不重写。
- 四阶段可由主 agent 本地顺序执行，但写作、润色、checker 和主审证据均可定位。

## 分开判断完成

| 判断 | 通过条件 |
|------|----------|
| 本批完成 | 本批正文及各阶段有效报告齐全，红色清零或修复复审通过，主终审与必要跨卷审查完成，接受实绩已入账 |
| 用户范围完成 | 用户指定的全部范围与深度已完成，未用局部批次冒充全量 |
| 下一批可开工 | 后续规划已吸收实绩，新包验收通过并唯一激活，无未解决的依赖阻塞 |
| 全书完结 | 全书目标、终章及必要全书收束审查完成；不能仅凭末批完成或文件数量判断 |

无下一批不要求造包。本批完成不以存在下一包为条件；继续下一批必须有有效包。授权范围内通过闸门即可续批，仅遇到必须由用户决定的方向、权限边界或无法补证的硬事实才请求处理。
