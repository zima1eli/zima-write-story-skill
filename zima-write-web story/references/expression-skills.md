# 表达阶段主用 skill 分工

正文流水线的表达工作分两段，各由一个专门 skill 主用。两个 skill 都不覆盖事实裁决，也不生成或登记执行包。

| 阶段 | 主用 skill | 它的定位 | 配套兜底 |
|------|------------|----------|----------|
| 初稿（写前与正向生成） | `human-writing` | 从零写：人物目标、场景变化、对白意图、视角细节、场景与概述交替 | `human-writing-fiction.md` |
| 润色（改稿） | `humanizer-zh` | 编辑已有文本：空话、重复与模板化表达，保留事实、确定程度和作者声音 | `humanizer-zh-fiction.md` |

分工理由：初稿是从无到有的生成，需要的是"让人物自己把事做出来"这类正向生成原则；润色是拿已有文本做定点修改，需要的是"保留原意与作者声音、逐条判断是否真有问题"这类编辑约束。两者混用会把润色的删除倾向带进初稿，也会把初稿的扩张倾向带进润色。

## 解析顺序

两个主用 skill 是外部安装项，不随本 skill 打包。按下面顺序解析实际路径，并由主 agent 在阶段报告里记录解析到的实际路径和版本：

1. 当前会话的可用 skill 列表中存在 `human-writing` 或 `humanizer-zh` 时，直接加载该 skill。
2. 否则在常见的用户级 skill 目录中查找同名 skill（如 `C:\Users\ai\.agents\skills\<name>` 或 `~/.agents/skills/<name>`）。
3. 仍不可用时，退回本 skill 内的兜底参考文件，并在报告里注明"本次使用兜底，未加载外部 skill"。

兜底文件是外部 skill 的小说语境适配摘录，不是替代品。外部 skill 可用时以它为准；兜底只在外部 skill 缺失时保证流程不中断。

## 使用规则

- 初稿阶段以 `human-writing` 为主用 skill，读取其虚构写作参考（该 skill 内的 fiction 参考文件）。`human-writing` 的通用硬禁项（破折号、冒号、三项以上同构排比、翻案句式）面向现代白话散文，在小说里按语境判断，不整体照搬；本书风格配置和 `human-writing-fiction.md` 的差异表优先。
- 润色阶段以 `humanizer-zh` 为主用 skill，读取其"编辑约束与优先级""模式的使用方式"和"交付前核对"。它的 31 条模式是检查线索，不是词语黑名单：每条命中都要回到上下文判断是否空泛、重复、歧义或与文体不符。
- 两个 skill 都不得越权：不能改事件顺序、关键动机、世界规则、道具实态、伏笔窗口或术语知晓时间，不能补造原文没有的事实，不能新增未经规划允许的信息交接。
- 外部 skill 的示例是通用中文语料，不是本书样章。作者声音以本书已接受正文为准，不用外部示例的语域覆盖本书声音。
- 通用源不预设本书的术语禁区、题材、保留句式或标点密度；只采用实际配置、用户要求和已接受正文有依据的约束，缺失时不补造。
- 润色时若外部 skill 的建议与本书硬门冲突，以本书硬门为准，并记录冲突项交主 agent 裁决。

## 与事实审查的边界

新写从人物要做的事起笔。已有稿按作者授权决定只审、局部润色或重写，见[交接契约](handoff-contract.md)。只在关键替换可能改变口气或含意时对读原句，跨场读来雷同时才做[相邻场景审读](scene-review.md)。强去 AI 味也沿用本书声音；中文问答、新闻和其他语种的习惯只作查疑线索。

`human-writing` 和 `humanizer-zh` 都只管表达。outline-checker 负责硬点覆盖、事实、连续性、伏笔和红线，不因表达 skill 的建议而增加文笔评分，也不把表达模式命中升级为事实问题。

主 agent 验收表达改动时，核对的是关键事件、因果、人物关键选择、信息来源、伏笔、慢场景与高潮过程是否完整，以及人物声音、POV、长短句与指代是否符合本书风格。不用"更自然""去掉 AI 味"这类笼统结论代替可见差异。
