# 上游交接契约

`zima-scroll-rod-and-chapter-outline` 负责卷纲、章纲、技法包和卷级审查；`zima-write-web-story` 负责正文、润色、校对和终审。二者保持上下游，不合并。

## 正文写作前必须确认

| 材料 | 正文阶段用途 |
|------|--------------|
| 当前执行包 | 批次开工许可证，集中承接当前事实、硬门、软门、分章施工卡、回读触发器和验收表 |
| 本批输入包 | 承接上游规划、前置事实、分章施工图和风险 |
| 当前卷纲 | 固定卷级目标、阻力、高潮、代价和回报点 |
| 本批章纲 | 固定章节范围、任务、必要条件、冲突和钩子 |
| 每章技法包 | 指导正文每章 1-3 个技法如何落地 |
| 伏笔/回收表 | 防止伏笔遗失、提前回收或强行回收 |
| 人物状态 | 保持动机、关系、资源、伤势和认知连续 |
| 术语认知约束 | 防止角色首次知晓前使用正式术语 |
| 角色认知路径 | 防止姓名、身份、旧事、地点、规则或道具来源无信息来源 |
| 关键道具状态路径 | 保持道具取得、损坏、转手、失效和使用连续 |
| 卷级接口卡 | 承接前卷并给下一卷输出状态接口 |
| 单卷/跨卷审查报告 | 承接已知偏差、修复项和下一批风险 |
| 项目进度 | 确认当前阶段、已完成范围、红色问题状态 |

## 缺失时的处理

- 缺当前执行包：暂停正文，由主 agent 在上一批终审、状态更新和 A/B/C/D 反馈吸收后生成。
- 缺当前卷纲或本批章纲：暂停正文写作，请先补上游产物。
- 缺技法包：可按 `references/wiki-routing.md` 生成本批技法包，但不要改章纲结构。
- 缺伏笔表或人物状态：先读取项目进度、memory 和上批终审报告补足；仍不足时标为风险。
- 缺术语认知约束：创建或更新当前卷术语认知状态表，并在本批报告中说明依据。
- 缺审查报告：可以继续普通批次，但卷末、跨卷或大纲偏离时必须先做审查。

## 不应做的事

- 不因交接缺失而通读上游 skill 全文。
- 不在正文阶段重写卷纲、章纲或卷级目标。
- 不把项目专属人物、卷名、专项技法回灌到通用源 skill。
- content-writer、polisher、outline-checker 不得生成、修订或登记下一批当前执行包。

## 既有正文接管

已有正文时先提取正文实绩基线，旧卷纲/章纲是可修订规划。A/B级只记录或更新状态，C级调整后续输入，D级才暂停并修复旧文或上游系统冲突。

## 当前执行包与下游反馈

当前执行包在上一批终审、状态更新和 A/B/C/D 反馈吸收后生成，并登记为 active。正文、执行包、章纲或卷纲不一致时，不默认某一方必错：A只记录，B更新状态，C修订后续规划，D暂停回上游。未登记 active 执行包时，不得开始下一批正文。
