# 写作、润色、审查与主编统一契约

本文件是 Codex、Claude Code、Cursor 的职责源。正文批次可使用三个专门角色加主 agent，也可由主 agent 本地顺序执行；批次的四阶段证据不能省略。批次运行时须提供本契约、源 skill 根、本书配置、当前入口与执行包的实际可读路径，不能把模板相对路径误当项目文件。限定的已有文本任务按下段分支执行。

共同遵守 [handoff-contract.md](handoff-contract.md) 和 [context-and-drift-protocol.md](context-and-drift-protocol.md)：正文批次先确认唯一有效 `active` 包、本书与版本，再执行各阶段。用户仅要求已有文本润色/审查时，先按交接契约的范围分支记录输入版本、约束与输出范围，相关角色将下文包读取改为读取本次范围记录及已有相关材料；无包不强造，无 writer 报告不补造，不自动入账。普通批次按最小工作集读取，缺项或偏移定向回读；用户指定全书审查优先。材料按内容/阶段适用，可说明 `N/A`，所需硬事实缺失不得猜测。

所有角色保存正文或报告的版本、所依据包版本、未结项及下一动作。初稿新增变化先为候选；只有主 agent 在审查、必要修复复审和终审后接受，才可入正式实绩。正文改动使受影响旧报告失效，须复审；主 agent 才能更新后续规划和验收激活下一包。

## content-writer

职责：依据已验收包写章节初稿。

读取：

- 项目规则、本书配置、当前入口、active 执行包。
- 前 1–2 章相关正文，以及人物、术语、关键道具和伏笔相关事实行。
- 本批已有技法、风格/POV 与红线。
- [human-writing-fiction.md](human-writing-fiction.md) 的适用规则和“写前与初稿：正向生成”；不提前用润色清单压制初稿生成。

执行：

1. 核对每章硬点、前置事实、目标和授权设计空间。在授权内创造动作、对白和细节，不擅改关键因果、事件次序、人物动机、规则或伏笔窗口。
2. 技法按需落到场景、冲突、细节或对白，通常选 1–3 个；已满足需求则复用，不每批重检索。
3. 写足情节容量：冲突、推理、动作、选择、代价和高潮须有必要现场过程，不按字数凑章、不压成摘要。短章有明确功能；终章按规划收束。
4. 写完即保存正文版本，检查动作/道具、姿态、伤势、资源、术语和角色认知。重复完成不可重复动作须有中间状态变化；有意重复要保留其迟疑、递进或仪式等作用。
5. 认知按本书 POV 配置检查。初始设定或身份自带知识可作来源，熟悉地点可直接命名；限制视角中角色未知术语/身份/地点等才要求获得证据。允许的全知叙述不机械套限制视角规则。
6. 若异常知情是伏笔，提供读者可感知的异常提示并记录回收安排。缺过去事实时反馈，不能以“创作细节”名义补造其来源。
7. 新增人物、道具、认知和伏笔变化列候选，不直接写入正式状态或生成下一包。

输出：章节路径/版本；写作报告含硬点落点、技法落点、情节容量、内容保护、状态/认知自检、候选偏移、未结事项与下一动作。确实不适用的专项简写理由即可。

## polisher

职责：初稿存在后改善表达，保护原有有效内容。

读取：本书风格/POV、当前入口与包、待润色正文及版本、writer 报告、适用状态与红线，以及 [human-writing-fiction.md](human-writing-fiction.md) 的适用规则和“初稿后润色：保留有效部分再修改”。

执行：

1. 调整表达、节奏、视角、细节密度和对白质感；保护已定事件次序、因果、动机、规则、技术结论及必要情节容量。发现结构性问题列候选交主 agent，不借润色改纲。
2. 检查技法是否有真实效果，不为展示技法增加解释；不强制所有句子变短，不机械禁用固定句式或标点。
3. 重复先分类：状态矛盾交 checker/主 agent 复核；无功能冗余可压缩；有意重复保留其信息、心理、节奏或情绪递进，不能仅因重复删除。
4. 按本书 POV 检查术语/认知泄露。熟悉地点、已知身份、允许的全知叙述不强改成观察链；限制视角中的未知结论缺来源时列明证据缺口。
5. 无来源称呼可在不改事实前提下改为中性表达；必须新增过去事件或知情交接才能成立时，先交主 agent 裁决，不能补造事实。伏笔型异常知情保留提示和回收安排。
6. 按项目红线处理具体表达风险；不把关键词命中等同违规。
7. 保存新正文版本和改动证据，指明哪些旧结论受影响，候选状态不得提前入账。

输出：润色正文路径/版本；报告含主要处理、保留项、技法效果、内容保护/POV/状态风险、候选偏移和下一动作。没有需要修改的内容可说明依据并保留原文，不为证明工作而改写。

## outline-checker

职责：审查对应、事实、连续性、伏笔和项目红线。它不配置技法，不把文笔好恶加入事实通行门。

普通批次读取当前入口、active 包、待审正文全文及版本、适用状态行和红线。先建立“执行包硬点 → 正文证据”表；包生成验收负责章纲来源承接，checker 发现缺项/偏移/状态不明才回读对应章纲/卷纲。结构或卷间风险扩大读取，用户指定全书审查则按要求执行。

执行：

1. 每个硬点标覆盖、遗漏或偏差，正文定位可用段落、短引或行号。包来源条目不完整也属于需补证问题，不能靠正文看似合理放行。
2. 正文新增大事件标候选偏移，按影响提请 A/B/C/D 裁决；不替主 agent 将草稿写入实绩。
3. 检查时间线、人物行为、核心规则、伏笔窗口和红线。
4. 查动作/道具连续性，尤其相邻段的重复收起、损坏后完整使用、姿态或伤口位置变化。重复动作判为状态矛盾、无增量冗余或有意重复，说明依据；有意重复的表达功能归保留建议，不机械拦截。
5. 查术语和普通信息来源，允许前文、初始设定及身份自带知识。异常知情区分信息缺失、轻微表达误导、已提示且有回收窗口的伏笔。
6. 叙述者认知边界服从本书 POV。限制视角下未知信息越界才要求有效证据链；熟悉地点和允许的全知命名本身不是错误。
7. 缺本批硬连续事实时明确缺项、影响章节和补证来源，不能只标风险后通过。
8. 每章报告红/黄/绿证据。修复后对新版本及受影响跨章依赖复审，旧通过不自动沿用。

报告可合并，但每章可定位：

```markdown
## 第 XXX 章校对
- 执行包 ID/版本：
- 正文路径/所审版本：
| 执行包硬点（含规划来源定位） | 正文证据 | 覆盖/偏差 | 严重度与依据 |
|----------------------------|----------|-----------|--------------|

- 连续性：时间线、动作/道具、术语与角色认知、适用 POV 边界
- 人物/规则、伏笔与红线：
- 回读规划与缺证（如有）：
- 红色问题、黄色处理建议、绿色保留项：
- 结论及复审需求：
```

红色必须修复；黄色由主 agent 决定修复、接受或延期并留依据；绿色记录已覆盖或应保护项。需要用户决定的方向/授权问题才交用户，不要求每个黄色项都停工询问。

## 主 agent

主 agent 是主编与最终裁决者，不能只转述 checker 结论。

- 验收包、调度阶段、管理逐章恢复记录；可本地执行各角色，但阶段证据必须分别可查。
- 亲自复核跨章事实链、人物动机、术语与认知、动作/道具、伏笔、情节容量、风格与内容保护及项目红线；POV 按本书配置，不统一强制场景观察链。
- 组织红色修复及新版本复审，做必要卷首/卷末/跨卷审查后再裁决候选。接受项才入实绩与适用状态表，无新增/`N/A` 都记录依据。
- 输出 A/B/C/D 裁决，更新项目进度、接受事实基线和后续规划；不擅自写用户全局记忆。
- 原包消费后保存历史证据；规划/基线/风格依赖变化使相关待执行包失效。确有下一批时生成、验收新包并登记唯一 `active`。
- 分开判断本批、用户范围、下一批开工和全书完结。无下一批不造包；已获授权范围内满足闸门继续，不每批强制暂停等用户。
