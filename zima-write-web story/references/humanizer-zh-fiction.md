# humanizer-zh 小说润色适配

本模块是 `humanizer-zh` 在小说润色场景的兜底参考。外部 `humanizer-zh` skill 可用时以它为准（见 [表达阶段主用 skill 分工](expression-skills.md)）；本文件在外部 skill 缺失时保证润色阶段不中断，并固定小说语境的边界。

## 适用与优先级

执行顺序以当前用户明确要求、本书已核准的世界规则与 POV、章纲硬点及已接受正文实绩为先。本书风格依据来自上游按大纲、用户要求和授权样文生成的 profile / style-guide，来源版本随执行包传递。未知风格标为待定或本轮设计，不冒称用户已经指定。通用编辑建议只在这些边界内起作用，不强加论坛长帖口吻。

- polisher 确认初稿已经存在后才使用本节，不在初稿前加载。
- 外部 `humanizer-zh` skill 可用时，加载其 `SKILL.md`，本文件只用于补充小说语境的边界与差异。
- 主 agent 验收表达改动与内容保护；outline-checker 仍只审事实、覆盖和连续性，不承担新增文笔评分。
- 主 agent 传入 `skill_root` 和本书材料的实际路径；本文件路径由 `skill_root` 解析。不要假定项目工作目录等于 skill 目录，也不要把本书专名或风格写回通用源文件。
- 本模块不预设任何书的禁词、破折号密度、题材或保留句式。专项约束必须来自本书实际配置、用户要求或已接受正文；材料未提供时不冒称已有约束，按当前文段功能判断并标注待定项。

## 润色的基本约束

沿用 `humanizer-zh` 的编辑优先级顺序：先保留信息和确定程度，再遵守本次编辑范围与文体，然后匹配作者声音，最后处理具体表达问题。

1. **不增加原文没有的事实。** 不新增事件、数字、名字、日期、经历、引文、来源或结论；不丢失独立信息。保留否定、比较对象、范围、条件、时间、完成状态和归因。不把相关改成因果，不把可能改成确定，不把计划改成已经完成。
2. **不越权改情节。** 不改事件顺序、关键动机、世界规则、道具实态、伏笔窗口和术语知晓时间。已经发生的信息交接可以改清楚表达；需要新增一次交接事件才能成立的修复，报告结构性候选交主 agent，不在润色里写定。
3. **匹配本书声音。** 有已接受样章时借鉴其句长、用词、标点和叙述习惯，不把样章里的经历、事件或专名移入正文。没有样章时保留输入的语域，不为了"有人味"添随机粗口、错字、网络口癖或凭空道具。
4. **只处理确实存在的问题。** 模式清单是检查线索，不是词语黑名单。没有问题的段落可以原样保留；不为证明工作量而改写已经通顺的文字。

## 模式清单的使用方式

`humanizer-zh` 的 31 条模式按六组组织，在小说润色中的取用方式如下：

| 组 | 主题 | 小说场景取用 |
|----|------|-------------|
| A | 铺垫代替陈述 | 查"不是 X，而是 Y"、单句收尾、格言、起跑式铺垫、与假想敌辩论。人物纠正真实误解、或推翻自己在前文立下的错误判断时保留；只用于抬价的假对比改掉。章末钩子本就是单句收尾，不按"碎片合并"处理。 |
| B | 公式化节奏 | 查强凑三段式、句式开头复读、破折号当万能连接、限定词堆叠、生造复合词、被动与缺主语。人物口语的排比与顿挫是声音，不按公式化删。 |
| C | 拔高与借权威 | 查 AI 高频词、意义拔高、模糊关联、句尾补充式拔高、宣传语、借权威、回避"是／有"。若本书实际配置明确了术语禁区，按该禁区检查；没有此依据时，不因词语偏学术就判为红线。 |
| D | 公式化排版 | 查粗体当装饰、装饰性标题、引号与中文标点。正文不用粗体；标题层级按本书目录，不动。中文正文用中文标点，但人物原话和特殊格式按本书风格保留。 |
| E | 聊天与草稿残留 | 查客服腔、知识边界免责与猜测填充、首句复读标题、谈论上一稿。删除没有剧情功能的套话和"前文改成什么"这类编辑痕迹；角色身份、对白或书信有意使用的表达按实际语用保留。 |
| F | 中文表达的补充检查 | 查层叠的"的"、"进行＋动词"、被字句堆叠、四字词排比、"随着……的发展"式开头、套话收尾。"不是 X，是 Y"若承担真实纠正或人物表达功能，应保留其信息；具体句式约束以本书实际配置为准。 |

每条命中都回到上下文判断：是否空泛、重复、歧义或与文体不符？单个词、标点、三项列表或四字词本身不构成修改理由。

## 小说语境的差异

`humanizer-zh` 的通用编辑规则与小说表达不完全一致，以下以本书为准：

| `humanizer-zh` 通用做法 | 本项目适配 |
|-------------------|-----------|
| 模式只作检查线索，不构成自动改写理由 | 沿用该原则，先判断语用功能、信息与文体，确认存在具体表达问题再修改。 |
| "不是 X，而是 Y"作为待检查句式 | 保留真实纠正、比较和否定承载的信息；只清理只抬价不提供信息的假对比。不能仅凭句型认定必须删除或属于本书特殊保留项。 |
| 装饰性标题、客服腔等通用场景 | 按本书体例与剧情功能判断，不为凑检查项生造改写，也不把有意使用的角色对白或书信当成编辑残留。 |
| 拆掉表演性中文以贴近自然表达 | 若本书配置或已接受正文采用旧白话、行话等语域，保留有效表达，不强改成现代口语腔；不据此预设本书题材。 |
| 合并重复信息 | 重复分三类：状态矛盾交 checker 与主 agent；无增量冗余可压缩；有意重复保留其信息、心理、节奏或情绪递进功能。 |
| 不机械禁用固定句式或标点 | 破折号、冒号、纠错对白、转折、排比按语境判断，都不是自动失败项。本书明确禁用的表达按本书红线执行。 |

## 交付前核对

- 每个新增的具体信息是否能在原文或已接受正文中找到？不能就撤回。
- 独立信息、否定、限定、时间、范围、归因和人物立场是否完整？有没有把"可能"写成"确定"？
- 调整列表、排比或句式后，是否丢失内容或添出新项目？
- 关键选择、推理与高潮是否被压成摘要？被压成摘要就恢复必要过程。
- 样本和文体是否得到尊重？没有问题的地方是否被强改？
- 道具实态、伤势、资源、术语知晓时间和伏笔窗口是否仍然连续？

输出润色后的正文及单独报告：输入/输出正文版本、执行包版本、`local` 或 `delegated`、证据路径、主要改动、受保护内容及依据、未解决问题和结构性反馈候选。只有主 agent 能接受变化并更新权威状态。改动后的正文交 outline-checker 审查；旧版本报告不能直接用于新稿验收。
