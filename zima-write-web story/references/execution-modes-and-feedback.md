# 正文执行模式与反馈闭环

## 执行模式

| 模式 | 触发 | 默认粒度 |
|------|------|----------|
| 迁移接管档 | 已有正文接入新流程 | 已写范围整体提取事实 |
| 标准批次档 | 普通推进、关系推进、常规副本 | 约10章 |
| 标准加强档 | 高密度推理、规则释放、术语或身份线索集中 | 约5章 |
| 严格审查档 | 卷末、跨卷、红色问题、核心规则/身份/伏笔集中释放 | 1-3章，写完即审 |

用户指定范围优先；主 agent 发现风险升级时应说明理由。

## 下游反馈单

每批结束输出短而可执行的反馈：

```markdown
## 下游反馈单

- 批次：
- 执行模式：
- 反馈级别：A / B / C / D
- 问题类型：章纲偏差 / 术语认知 / 角色认知 / 道具状态 / 伏笔窗口 / 节奏 / 红线
- 正文证据：
- 对后续影响：
- 建议动作：记录 / 更新状态 / 修订下一批规划 / 暂停回上游
```

| 级别 | 动作 |
|------|------|
| A | 只记录 |
| B | 更新状态表、接口或风险 |
| C | 下一批章纲、输入包或当前执行包必须吸收 |
| D | 暂停正文，先修上游规划或旧文红色问题 |

同类黄色问题连续出现两次，至少按 C 级处理，说明上游输入存在系统缺口。
