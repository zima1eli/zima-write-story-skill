# 正文执行模式与反馈闭环

## 执行模式

| 模式 | 触发 | 默认粒度 |
|------|------|----------|
| 迁移接管 | 已有正文接入流程 | 提取有效已接受范围，未审草稿单列 |
| 标准批次 | 普通推进、关系推进、常规情节 | 约 10 章 |
| 标准加强 | 高密度推理、规则/术语/身份线索集中 | 约 5 章 |
| 严格审查 | 卷末、跨卷、红色问题、核心规则/伏笔集中释放 | 1–3 章，写完即审 |

用户指定总范围和深度优先。主 agent 可因风险缩小执行批次并说明原因，但持续完成授权范围，不把默认粒度当任务终点。

## 下游反馈单

每批留下短而可执行的反馈，可与主审报告合并：

```markdown
## 下游反馈

- 本书 / 批次 / 执行包 ID 与版本：
- 所审正文版本及证据：
- 候选变化与问题类型：
- 反馈级别：A / B / C / D
- 对当前连续性、后续章节及卷目标的影响：
- 主 agent 裁决：接受 / 修复后复审 / 驳回 / 待补证
- 已接受实绩及入账位置：未接受时不填正式事实
- 后续规划或包处理：
- 阻塞、当前阶段与下一动作：
```

A/B/C/D 判断以 [context-and-drift-protocol.md](context-and-drift-protocol.md) 为准：A 记录表达变化，B 接受后更新状态，C 吸收进后续规划，D 暂停依赖并重审关键冲突。C/D 不自动意味正文一定错，也不授权把未审稿直接升为事实。

同类黄色问题连续出现两次，检查是否存在系统缺口；确实影响后续规划时升级 C。仅表达层复发可定向刷新技法或润色指引，不凭出现次数一律修改章纲。

反馈吸收顺序固定为修复复审 → 主审及必要跨卷审查 → 接受实绩入账 → 更新后续规划 → 新包验收激活。无下一批则记范围结束，不制造空包；没有未解决依赖且仍在授权范围内，不每批例行等待用户确认。
