# zima-fiction wiki 路由表

文风模块决定这本书怎么叙述、人物怎样说话。场景技法解决本章的具体写作问题。首批已有技法包时，仍要确认文风模块。本书的 POV、已定声音和章纲硬点优先。

默认知识库根目录（项目明确配置了其他文风库时使用该库）

```text
D:\knowledge base\zima-fiction
```

## 文风模块选用

1. **从本书取依据。** 首次接手新写或续写，主 agent 先读大纲里的整体基调、叙述视角和人物关系，再读目标章纲和执行卡里的关键场面、对白意图和信息揭示顺序。核对用户要求、上游风格依据、授权样文及已接受正文。已有明确模块和可执行写法，沿用该记录。仅有“武侠”“节奏快”等标签时，还需选模块。
2. **进库读模块原页。** 在默认库内先看 `wiki/话题/标签/文风.md` 或 `wiki/话题/标签/作者文风.md`，按目标声音、叙述距离或对白方式跟到文风总纲、单书专题或具体写法。标签未收录时，在 `wiki/话题` 按同一组词定向检索。读候选页的适用场面、具体写法与边界，再按本书需求选定。知识库检索服务未接入时可直接读本地 Markdown。只有打开并核过内容的页面才能列为来源。
3. **确定本书怎么写。** 有明确匹配时，告诉作者选哪个模块、为什么适合本书、准备怎样写当前场面，随后按已授权范围推进。局部技法只适用一场时，仍须明确其余章节沿用的主风格。几种可行方向会明显改变全书声音时，交给作者取舍。无可用知识库或无合适模块，且文风仍未定时，拿执行卡中的同一个场面给出两三种可选写法，说清读者会先看到什么、人物怎样开口。请用户选择、调整或给出样文，选定后再写正式正文。用户已明确指定的自定义写法可直接落实，来源记为用户选择。
4. **随包传递。** 在现有本书配置或风格记录中保存模块名、来源（实读页面的库内路径与版本，或用户选择及其定位）、适用范围和关键写法。当前包引用该记录及版本，并在执行卡注明本章怎样使用。书级主风格与只适用一场的局部写法分开标明。续章复用有效记录，换章或换会话只核对本章落点；用户改口径、记录缺失或与新场景确实冲突时，才回到相应步骤。改动影响现有包时按交接契约重新验收。

例如，章纲里两方谈条件、各有保留，可读 `wiki/话题/金庸古龙/写作技法/古龙对白的试探与信息留白.md`。若贴合本书，可只用于这场谈话，让一方的还价暴露他肯让到哪一步。买票问价这样的日常对白仍按人物原有口吻写。借用表达方法，场面、人物和台词由本书产生。

## 缺技法时的导航

首次需要从本知识库补技法时，用以下相对于 `wiki/` 的导航定位。已有可用技法包时直接复用。

- `index.md`：全局索引，用 `rg` 定位相关模块。
- `话题/00-素材库导航.md`：拆书轨、创作轨、标签轨说明。
- `话题/标签/00-标签导航.md`：标签聚合入口。
- `话题/标签/_taxonomy.md`：标签关系。
- `话题/方法论/00-类型导航.md`：写作技法、结构技法、文本细读入口。

常用命令：

```powershell
rg -n "关键词1|关键词2|关键词3" "D:\knowledge base\zima-fiction\wiki\index.md"
rg --files "D:\knowledge base\zima-fiction\wiki" | rg "关键词1|关键词2"
```

## 场景元素借鉴

### 拳拳到肉的打斗

检索：

```powershell
rg -n "鲁提辖拳打|醉打蒋门神|景阳冈|拳|擂台|以伤换命|老拳师|BOSS战|数据化战斗" "D:\knowledge base\zima-fiction\wiki\index.md"
```

借鉴方式：

- 拆目标：谁要逼谁先动、谁在保留底牌、谁在争取时间。
- 拆节奏：试探、错位、短暂失衡、代价、反击。
- 拆环境：桌椅、雨水、灯光、地面、围观者，必须参与战斗。
- 写身体反馈，但避开血腥细节和暴力美化。

### 推理解密

检索：

```powershell
rg -n "推理|侦探|线索|证据|凶手|内奸|逻辑链|误导|排除|审判" "D:\knowledge base\zima-fiction\wiki\index.md"
```

借鉴方式：

- 至少有可回看证据，不靠灵感破案。
- 设计一条误导链和一条反证链。
- 揭秘时每个结论都对应前文物证、行为或语言。
- 高潮尽量让真相改变人物关系或局势，而不只是解答谜题。

### 灵异恐怖

检索：

```powershell
rg -n "恐怖|灵异|志怪|画皮|僵尸|歌谣|封闭空间|恐惧具象化|怪谈" "D:\knowledge base\zima-fiction\wiki\index.md"
```

借鉴方式：

- 从日常物异常开始，不急着露怪。
- 用空间限制、声音、气味、重复句式和信息缺口制造不安。
- 让线索本身带恐怖感，例如歌谣、旧档案、损坏的监控。
- 不宣扬真实迷信，不使用真实邪教名称。

### 商战/科技攻防

检索：

```powershell
rg -n "AI|科技|数字生命|意识共振|赛博朋克|权谋|博弈|心理战|垄断|数据|合规" "D:\knowledge base\zima-fiction\wiki\index.md"
```

借鉴方式：

- 把“打斗”转译成信息差、资源差、合规边界、舆论窗口和技术瓶颈。
- 对手不是愚蠢，而是基于旧优势做出合理误判。
- 技术描写写现象和影响，避免可复现攻击步骤。
- 会议和谈判必须有筹码变化，不能只是观点陈述。

## 技法包输出模板

已有技法包可仅记录本批复用与真实落点。新增或修订时注明来源、适用章节、解决的缺口及版本；通常每章选 1–3 个即可，不为凑数添加方法。知识库路径不可用时如实记录，可使用已核准技法或定向反馈缺口，不虚称已检索。

```markdown
## 本批次技法包

- 类型判断：都市·科技·AI·商战 + 推理解密元素
- 读取页面：
  - 话题/方法论/写作技法/怎样写故事6W原则-方法论提取.md
  - 话题/方法论/写作技法/章节悬念结尾法.md
  - 话题/网文无限流/情节与母题/推理式揭秘与侦探审判.md
- 章节应用：
  - 第201章：从冲突现场切入，用“但是”反转旧判断
  - 第202章：证据链三段推进，结尾留未回答问题
  - 第203章：商战谈判写筹码交换，不写空泛发言
- 红线风险：
  - 黑客步骤只写结果，不写命令和复现路径
  - 国安机构保持虚构，不写真实流程
```
