# human-writing 小说表达适配

本模块是正文流水线的默认组成部分，无需另装或另行调用外部 skill。它帮助人物通过行动、选择和语言成立；不授予改写章纲硬点或事实基线的权限。

## 适用与优先级

执行顺序以当前用户明确要求、本书已核准的世界规则与 POV、章纲硬点及已接受正文实绩为先。本书风格依据来自上游根据大纲、用户要求和授权样文生成的 profile / style-guide，来源版本随执行包传递。未知风格标为待定或本轮设计，不冒称用户已经指定。通用表达建议只在这些边界内起作用，不强加论坛长帖口吻。

- content-writer 默认读取本节与“写前与初稿：正向生成”，先落笔，不在初稿前加载下方逐项改稿检查。
- polisher 确认初稿已经存在后，读取本节与“初稿后润色：保留有效部分再修改”。
- 主 agent 使用“主 agent 终审核验”接受或退回表达改动；outline-checker 仍只审事实、覆盖和连续性，不承担新增文笔评分。
- 主 agent 传入 `skill_root` 和本书材料的实际路径；本文件路径由 `skill_root` 解析。不要假定项目工作目录等于 skill 目录，也不要把本书专名或风格写回通用源文件。

小说允许在授权空间里创造动作、对白、感官细节和场景衔接。判断标准是是否保持已定关键事件、因果、人物关键动机、信息来源、世界规则和伏笔回收窗口。局部创造使某项关键前提改变时，报告变化候选，由主 agent 裁决；不能先写入事实状态再倒推它合理。

## 写前与初稿：正向生成

只从 active 当前执行包、本书配置和必要前文提取眼前任务；执行包不足以确定关键事实时升级回读或报告缺口，不自行重排章纲。

1. **把人物放进当前处境。** 每个主要场景先明确 POV 人物眼前想完成什么、有什么阻碍、准备采取什么办法、失败要付什么代价。配角也有自己的即时目的，不只替主角递消息。性格通过选择、让步、隐瞒、失手和承担后果表现。
2. **让场景留下变化。** 场景结束时，信息、关系、风险、行动办法、理解或情绪应产生与章纲有关的变化。缓慢积累、暂不行动、等待与压抑也能形成变化；气氛递进、伏笔安置和必要铺垫是有效功能，不要求每段都有外部事件。
3. **让对白执行意图。** 说话可以试探、遮掩、争取、拒绝、拖延、安抚或保全面子。人物会回避、打断和只说一半；不要让双方为了读者重背共同已知背景，也不要让所有角色轮流替作者讲道理。声音来自身份、关系和压力，不靠统一口癖。
4. **让细节属于视角。** 根据本书 POV 选择人物会注意的东西，让细节影响动作、判断、关系或气氛。限定视角的信息需要观察、已有知识或可追踪的推断；采用全知等其他视角时遵守本书边界和切换标记，不能把限定视角规则强加给全书。
5. **用过程承载关键选择。** 关键冲突、推理、代价、关系变化、不可逆动作和回收点要写出足够过程，使读者看清限制、判断、行动及后果。重复劳动、无新信息的赶路和已知流程可以概述；不能把施工卡要求展开的场景压成剧情梗概。
6. **让语句随内容呼吸。** 长句可以承载复杂条件与关系，短句可以落动作和停顿；避免每段同长、连续短句敲出固定节拍。指向明确时自然省略主语，多人同场或跨段后容易误认时把名字补回来。
7. **给读者留下感受的位置。** 动作、物件或对白已表现出的情绪，不必紧跟一次同义解释。仍须写清读者无法自行补出的必要条件、人物选择和因果。设定在影响行动时进入正文，硬点要求的前置信息必须保留。
8. **让收束服务本章任务。** 依章纲留下已经形成的后果、选择或期待；本章需要闭合时允许安静收束，不能为“每章必须有钩子”擅造事件。开头物件回到结尾时，应有本书允许的关系或含义变化。

本书规定的篇幅、场景容量和展开深度优先。没有固定字数时按故事需要写足；不能用“自然简洁”绕过必要铺垫，也不能用空泛解释补足字数。写作报告记录实际落点与候选变化，正文不插入写作检查清单。

## 初稿后润色：保留有效部分再修改

本节只在初稿完成后使用。批次润色先读取同版执行包、初稿版本、写作报告、本书风格依据和相关状态；若用户只要求处理已给定文本，按 [交接契约](handoff-contract.md) 的范围分支读取本次文本版本、已有约束和必要上下文，不强造包或 writer 报告。明确允许覆盖的正文路径，改稿按问题影响定点处理，不设必须修改的段落数或删稿比例。

1. **先标出要保护的部分。** 记录人物声音、有效留白、有意重复、气氛层次、慢场景、伏笔、因果铺垫和关键场景容量。查看本段由何种人物目标、行动、认识变化或情绪积累支撑，再判断是否冗余。
2. **拆重复解释，不拆成立条件。** 同一情绪已经由动作清楚表现，可以减去其后的重复释义。涉及知识获得、行动资格、规则代价、道具状态、时空条件或关键动机的句子，即使不够顺口，也应先改写为更清楚的表达；不得以通顺为由删掉前置条件。
3. **听句子与指代。** 调整迟迟不出现的主语、过长定语和含混代词；长短句、段落长短和停顿跟随内容。对白可以省略、断裂、反复和答非所问，人物的犹疑或遮掩不能被润成说明文。古意、成语、口语和专业词按本书风格与人物身份判断，不统一改成一种腔调。
4. **回到当前人物和场景。** 空泛判断、装饰比喻、机械抬高段落的路标语，若没有场景功能，改为当前行动、关系或感受。小说意象可服务气氛与母题，不按意象数量删除；不能为了“有人味”添随机粗口、错字、网络口癖或凭空道具。
5. **结合语境处理句式和标点。** 破折号、冒号、纠错或转折句、排比、重复词及人物原话都不是本适配的硬禁项。先判断它是否有真实语用功能；例如人物纠正误会、故意误导、说话被打断或遵循仪式，都可能成立。只处理缺乏情节依据、替作者制造虚假深刻的写法。用户明确指定的禁用项另行遵守。
6. **按功能精简并复核容量。** 对无增量的赘述可试删、合并或重写，随后检查人物理解、气氛递进、伏笔、因果、硬点与场景容量是否受损。没有“三分之一”等固定删除目标。关键选择、推理与高潮若被压成摘要，应恢复必要过程。
7. **检查改动的事实代价。** 不改变事件顺序、关键动机、规则结论、人物信息来源、道具实态或伏笔窗口。已经发生的信息交接可澄清表达；需要新增一次交接事件才能解释知识来源时，报告结构性修复候选，不能作为润色直接写定。

输出润色后的正文及单独报告：输入/输出正文版本、执行包版本、`local` 或 `delegated`、证据路径、主要改动、受保护内容及依据、未解决问题和结构性反馈候选。只有主 agent 能接受变化并更新权威状态。改动后的正文交 outline-checker 审查；旧版本报告不能直接用于新稿验收。

## 主 agent 终审核验

审查表达改动是否在本书边界内改善阅读，并把结果留在批次证据里。不要用“更自然”“去掉 AI 味”等笼统结论替代可见差异。

- 对照改稿前后及执行包硬点，抽查必要条件、信息交接、人物关键选择、伏笔、慢场景与高潮过程是否完整；有损伤则退回定点修复。
- 核对人物声音、POV、长短句与指代是否符合本书风格。正常纠错对白、中断、排比、有意重复不得因词形命中被一律删除。
- 确认事实与覆盖审查针对最终正文版本；修复引起版本变化时，按影响范围复审，不复用旧结论。
- 记录采用、退回、保留及其证据，区分本批完成、授权范围完成、下一批可开工和全书完结。不为表达优化另造下一批，也不让子角色激活执行包。

以上核验是人工语义检查。规则文件存在、模板解析成功或正则未命中，只能证明对应的结构事实，不能证明文学质量。

本项目保留其人物行动、对白意图、视角细节、场景/概述分配、先保护有效部分再改稿等原则；以下是本项目小说适配的主动差异，不能声称为原版原有规则：

| 原版要求或默认值 | 本项目适配 |
|---|---|
| 默认长帖/现代白话散文语气，具体文体可覆盖 | 本书上游生成的风格配置直接优先，不强加论坛腔 |
| 标点、部分纠错/翻案句、排比与词语的硬禁令 | 降为语境提示，保护正常对白、悬疑纠错与人物声音；用户明确禁令仍有效 |
| 改稿压缩试验及删除无新增段落 | 无固定删稿比例，先核场景、气氛、因果、伏笔和容量功能 |
| 面向从零虚构的创造空间 | 允许约束内细节创造；不改已定关键事件、动机与回收窗口 |
| 对作品交付的简化呈现 | 正文保持纯作品，报告与恢复证据单独保存 |
| 原脚本以正则识别形状并判失败 | 不移植 `check_prose.py`，不将“词形清零”设为小说质量门 |

不复制非虚构材料采集分支，不新增外部 skill 依赖。本模块与角色契约协作，事实冲突仍按既有主 agent 裁决与复审流程处理。
