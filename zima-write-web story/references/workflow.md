# 正文批量写作工作流

普通推进可约 10 章，高密度推理/规则释放约 5 章，卷末高潮或高风险段 1–3 章，写完即审。用户指定总范围优先；批次只是执行粒度，不能把一批交付冒称整个任务完成。

## 0. 确认入口、接管与交接

先按 [handoff-contract.md](handoff-contract.md) 判任务范围：仅处理已有文本时执行请求的润色或审查阶段并保存范围证据，不要求完整开写包、不补造其他阶段、不直接入正式实绩。以下编号步骤用于新正文批次。

1. 读取项目规则、本书配置、当前入口与逐章恢复记录，确定总范围、当前批次、输出路径和执行模式。
2. 按 [handoff-contract.md](handoff-contract.md) 验收材料、包元数据及硬点来源。只有入口指向的唯一有效 `active` 包可以开写；本批硬连续事实缺失时定向补证，未解决前停在受影响处。
3. 零正文首批由主 agent 从已审规划、初始事实和风格配置初始化、验收并激活，不索取不存在的上批报告。
4. 已有正文接入时提取已接受实绩，保留通过章节；旧规划冲突做 A/B/C/D 裁决。未审草稿单列候选，不以落盘即事实。
5. 恢复任务核对实际正文/报告版本，续做未完成阶段，不从章首机械重写。

## 1. 技法、风格与风险准备

复用包内已验收技法，确认每章真实落点；仅技法缺失、新类型首次出现或同类问题复发才按 [wiki-routing.md](wiki-routing.md) 更新。读取本书风格、叙述视角、红线和授权设计空间；专项状态表按本批需要读取，无关项注明 `N/A`。

## 2. content-writer 初稿

先读 [human-writing-fiction.md](human-writing-fiction.md) 的适用规则与“写前与初稿：正向生成”。在章纲授权内设计动作、对白和细节，每章写完即保存版本、写作报告和下一动作。

字数由情节容量决定。冲突、推理、动作、选择、代价和高潮要有读者能经历的过程，不能只交剧情摘要；短章须有余波、过桥、单点反转或换气等功能。章末服务规划与节奏，终章允许完整收束。

检查动作/道具、伤势、资源与认知连续性。记录新增术语知晓、人物/伏笔变化及表达偏移，均先列候选；不越权更新正式事实表或下一执行包。

## 3. polisher 后置润色

初稿存在后，读取小说表达模块的适用规则与“初稿后润色：保留有效部分再修改”、本书风格、写作报告和当前包。改表达、节奏、视角与不必要解释，保护关键事件、因果、动机、规则、必要过程和有意重复。

不把任何词、句式或标点一刀切删除。POV 以本书配置为准，熟悉地点和允许的全知叙述可直接命名；限制视角中的未知信息才需相应获得依据。不能为了补认知链凭空新增未经规划允许的信息交接。

保存润色后正文版本、处理证据和待裁决问题，旧报告保留所审版本，受影响结论须重验。

## 4. outline-checker 审查、修复与复审

普通批次以“执行包硬点 → 正文证据”逐章核对，同时检查时间线、人物/世界规则、动作/道具、术语/角色认知、伏笔和红线。包中来源条目由生成验收承担；发现缺项、偏移或状态不明，再定向回读章纲/卷纲。用户明确要求全书审查时覆盖其总范围。

按红/黄/绿报告具体证据与所审正文版本。红色必须修复，黄色需有接受、处理或延期决定。修正文后使受影响旧报告失效，复审受影响章节和跨章依赖；没有复审证据不能进入接受实绩阶段。

## 5. 主 agent 终审及必要跨卷审查

主 agent 复核四阶段证据、跨章连续性、人物动机、动作/道具、术语认知、POV 边界、伏笔、情节容量、风格保护、红线和 A/B/C/D 候选裁决。可本地执行各角色，但不同阶段和版本的证据必须可定位，不以“已调用 agent”代替报告。

卷末、卷首、跨卷批次或结构偏离触发跨卷审查：检查相关卷目标、卷间状态、伏笔窗口、情绪收束和卷末/卷首正文。此项须在实绩入账与下一包激活前完成；不适用则记录理由。

## 6. 接受实绩入账与后续规划更新

终审明确接受后，才把候选写入人物、术语、认知、道具、伏笔与风险实绩，并记录依据正文/报告版本。适用但无新增写“无新增”，不适用写 `N/A` 及理由。更新项目进度与恢复记录；用户未授权的全局记忆不在此写入。

当前包标记 `consumed`，从可执行入口移除。回读当前入口、项目进度/逐章恢复与接受事实基线，核对已接受范围、包版本和下一动作；日志已经追加不代表其他当前记录自动更新。将接受结果及 C/D 裁决反馈到后续章纲、输入包和卷级接口；未解决的结构问题或矛盾进度阻断下一批激活，先定点修正并重验。不得先激活下一包，再补本批终审或跨卷检查。

## 7. 判断结束或激活下一批

分别记录：

- **本批完成**：当前范围正文、润色、审查、修复复审和主终审均有有效证据，已接受实绩入账。
- **用户范围完成**：用户要求的全部章节/审查深度已覆盖，不用本批数量替代。
- **下一批可开工**：确有后续批次，规划已吸收实绩，新包验收且入口唯一 `active`，依赖阻塞已解除。
- **全书完结**：全书授权目标、终章和全书层面的收束/审查均完成；某批或某卷完成不等于全书完结。

用户范围结束或无下一批时不造空包；在状态中写清停止原因和后续入口。授权范围内需要继续且通过闸门，直接续批，不每批强制等待用户确认。

## 批次记录

正文与报告可合并管理，但须能定位：

- 总范围、当前批次、已完成范围与当前章。
- 本包 ID/版本、规划/事实/风格版本。
- 每章阶段、正文路径/版本、各报告及所审版本、未结项、下一动作。
- 硬点覆盖、技法落点、内容保护、红/黄问题和修复复审证据。
- A/B/C/D 候选、主 agent 裁决、接受实绩及状态表更新/无新增/`N/A`。
- 必要跨卷审查结果、四种完成判断、阻塞与下一入口。
