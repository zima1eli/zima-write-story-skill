# 当前执行包与偏移处理协议

## 事实与默认工作集

大纲是规划源，执行包是校准快照，已接受正文是实绩；未经终审的草稿、新增细节和状态变化只是候选。正文与规划不一致时先审查、裁决，不默认任一方正确。

普通批次读：项目当前入口与本书配置、唯一 `active` 包、前 1–2 章相关正文、本章目标/草稿、术语/角色/道具/伏笔相关行、风格与红线。默认不通读全书、卷纲全文、全部旧报告、归档或 wiki。

发现包硬点缺失、来源不明、偏移或状态不明，先回读对应章纲段；结构风险读卷纲相关段；新书、新卷、卷末、跨卷、核心规则冲突或局部材料无法解答时扩大到全书必要材料。用户明确要求全书审查时，总范围优先，不能只交一个普通批次结果。

## 候选变化与裁决

| 级别 | 判断 | 主 agent 处理 |
|------|------|----------------|
| A | 表达变化，不影响已定目标与事实 | 核对内容保护后记录 |
| B | 授权情节内自然产生的状态变化 | 先标候选；终审接受后入人物、术语、道具、伏笔或风险实绩 |
| C | 变化需要后续规划吸收 | 暂停依赖旧规划的下一批；接受并入账后修订后续规划和包，或驳回并修正文 |
| D | 破坏卷级目标、核心规则、关键动机或伏笔窗口 | 暂停受影响正文，回上游重审或修正文，复审通过前不入账、不激活下一包 |

裁决考虑人物、因果、伏笔和读者体验，同时保留用户的硬约束。章纲授权内的动作、对白和细节可以新设计；改变关键因果或规则不属于普通扩写自由。黄色建议也要记录接受/延期及依据，只有需要用户决策的方向或授权边界才询问，不把全部黄色项变成例行停工。

## 版本失效规则

- 正文一经修改，依赖被改内容的旧报告对新版本的通过结论标为失效；记录新正文版本并按影响范围重做检查。历史初稿/润色报告仍保留其输入、输出版本的过程证据，不能拿旧“通过”给新文本背书，也不必回退重做整个流水线或重写未受影响的已通过章节。
- 规划、已接受事实基线或风格硬约束变化时，依赖它们的执行包失效；更新后重新验收。正文只是候选变化时先冻结受影响后续执行，不提前改正式基线。
- 重跑章节、用户改方向、卷间接续发现冲突时，记录具体影响范围与依赖，不把所有历史文件一律作废。已消费包保留历史版本；重新开启受影响范围时必须有重新验收的当前包。
- 状态流转和元数据以 [handoff-contract.md](handoff-contract.md) 为准；入口不得仍指向失效包。

## 中断恢复

每章保存最少一行可恢复记录：

| 章节 | 当前阶段 | 正文路径/版本 | 写作/润色/checker/终审报告及所审版本 | 未结事项 | 下一动作 |
|------|----------|---------------|--------------------------------------|----------|----------|

阶段可用待写、已初稿、已润色、待修复/复审、待主审、已接受。记录本批已完成范围、当前处理章、阻塞、执行包 ID/版本与下一入口。报告可以合并保存，但每阶段、每章和版本关系必须可定位。

恢复时核对实际文件与版本，先处理失效报告和未结项，从下一动作继续；已有通过证据且未受变动影响的章节不重写。仅有进度勾选、命令成功或退出码，不能替代对应正文和报告证据。
