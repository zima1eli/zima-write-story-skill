## 2026-10-12 · 项目生成交接、已接受实绩与小说表达

- 区分通用源 skill 与按本书生成的项目材料；按内容/阶段验收，可合并表单并记录 N/A，缺本批硬连续事实则定向补证，不猜测。
- 输入包保存规划依据，执行包保存基于已接受实绩的校准快照；补齐版本与来源元数据、验收证据、draft/active/consumed/invalidated 状态及当前入口唯一 active。
- 增加零正文首批初始化，保留既有正文接管；未审稿和新增状态只列候选，审查、修复复审、主审及必要跨卷审查通过后才入账，再更新后续规划和激活下一包。
- 逐章保存阶段、正文版本、报告、未结项和下一动作；正文修改使相关报告失效，规划/已接受事实变化使依赖包失效，恢复不重写未受影响的通过章节。
- 默认接入小说表达模块：writer 正向初稿，polisher 后置润色，主 agent 验收风格与内容保护；checker 保持事实职责。允许章纲授权内细节设计，保护必要容量和有意重复，POV 服从本书配置，终章可收束。
- 普通 checker 统一核对执行包硬点与正文证据，包验收承接章纲来源；缺项/偏移定向回读，用户全书审查优先。复用技法包，只有缺技法、新类型或复发才更新路由。
- 分开本批完成、用户范围完成、下一批可开工和全书完结；无下一批不造包，授权范围内不每批强制等待用户。四阶段证据可由主 agent 本地顺序执行。
- 独立审查后补已有文本润色/只审查入口：保存范围、版本和约束，不强造开写包或未执行阶段；限定交付不等于整批接收。反复黄色项按实际影响分级，不机械改纲。
- 两章实写暴露进度总表落后于运行日志：在续批激活和收尾前增设当前入口、进度/恢复、接受基线的一致性回读门，补针对性回归，保留原失败证据。
- 同步入口、全部现有 references 与三端模板职责；三端说明增加契约/表达模块的实际路径解析和运行验证边界。回归用例与实际验证结果以仓库评测记录为准，不将规则文本本身当作行为通过证据。

以下为历史记录，不是现行执行要求。较早版本的固定字数、统一场景观察链、每批检索/暂停、必造下一包等口径，由以上修订及当前 SKILL/references 取代。

## 2026-07-16 · 当前执行包、容量门与可见流水线

- 触发问题：历史项目复盘显示，通用正文流程仍残留“3000—4000 字”硬目标，普通批次可能过度读取全量上下文，四角色流水线缺少可见报告，而且主 agent 完成终审后没有统一生成并激活下一份执行包。
- 影响范围：`SKILL.md`、正文工作流、质量门、交接合同、agent 合同、三端运行时模板、回归样例和变更记录。
- 修改内容：
  - 普通批次改为“当前入口 + 当前执行包 + 风险定向回读”，只有新项目、新卷、跨卷、卷末或偏离风险时才扩大读取范围。
  - 新增既有正文迁移的事实基线；旧计划与已落盘正文冲突时，不机械覆盖正文，先按 A/B/C/D 反馈分级处理。
  - 批量大小按稳定段、收束段、风险段动态采用 10 / 5 / 1—3 章；章节长度由场景容量和功能决定，不设固定字数硬门。
  - content-writer、polisher、outline-checker 与主 agent 均需留下可见报告；主 agent 终审后负责生成并激活下一份执行包，在此之前不得启动下一批。
  - 新增 `references/context-and-drift-protocol.md` 与 `references/execution-modes-and-feedback.md`，并同步 Codex、Claude Code、Cursor 三端模板。
- 边界：本次只沉淀跨项目可复用规则，没有把具体小说的人名、章节号、项目路径、封面尺寸或单章措辞写入通用技能。
- 新增 eval：第 11—14 条分别覆盖既有正文与旧计划冲突、缺失当前执行包、短章容量判断、四角色报告不可见。

## 2026-06-27 · 叙述者认知边界硬门

- **触发问题**：第003章"灯重新亮起来"后场景切换，叙述者直接写"他站在一间像从旧年间搬出来的丧铺里"——"丧铺"这个确定标签出现在沈渡通过观察和推断之前，属于叙述者越过了角色的认知边界。之前修复只加了"像"字做表面软化，没有解决结构问题：确定标签必须放在感官证据链之后。
- **与角色认知链的区别**：角色认知链管的是"角色说出自己不知道的信息"（姓名、称呼、身份等），叙述者认知边界管的是"叙述者替角色越级认知"（场景标签、地点标签、身份标签、时代标签在角色观察和推断之前就被叙述者确定命名）。两者同属"POV 认知一致性"范畴，但犯错主体不同。
- **影响范围**：content-writer 初稿必须按"观察→临时称呼/感官描述→积累证据→推断并确定标签"的顺序写场景切换，不能角色刚进陌生空间就由叙述者贴全知标签。polisher 必须检查场景切换段落的标签顺序，发现提前标签改为感官证据链。outline-checker 必须把场景标签前置标为黄或红，不能当作普通文笔问题放过。主 agent 终审兜底。
- **修改文件**：
  - `templates/claude/agents/content-writer.md`：新增叙述者认知边界自检规则。
  - `references/agent-contracts.md`：content-writer 新增第10项、polisher 新增第9项、outline-checker 新增第10项（原10/11重编号为12/13）、主 agent 新增复核项。
- **新增/修改 eval**：eval 第10条已覆盖此场景（要求识别"民国时期的丧铺"为场景标签前置/叙述者认知越界）。
- **后续观察**：后续写作报告和审查报告应同时出现"角色认知链"和"叙述者认知边界"两项检查结果；场景切换卡（尤其是副本/新地图入场）是高频风险点，content-writer 在写这些段落时必须先列感官证据再下结论标签。

## 2026-06-26 · 动作状态审查与有意重复保护
