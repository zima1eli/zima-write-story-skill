## 情境 1：active 包 v1/F0，已接受事实已到 F1，文件被改名 v2，用户要求开写

**应答：**“当前包仍依赖 F0，而 F1 已有影响开章的接受事实；把文件名改成 v2 不构成重新验收。我会先校准受影响的开章条件、修订并验收执行包，恢复唯一有效入口后继续开写。”

**动作序列：**

1. 核对当前入口、包内 ID/版本、事实基线引用、F1 接受证据，以及影响开章的具体事实。根据情境给定事实，已有足够理由判定相关未消费包失效，不能因文件名或 `active` 字样放行。
2. 将依赖 F0 的受影响包记为 `invalidated`，记录 F0 → F1 的原因与影响范围，从可执行入口移除；保留历史版本。查明被改名文件的真实内容，不把文件名当作包版本证明。
3. 依据 F1 修订受影响的后续规划、输入包引用和执行快照。新修订先为 `draft`，记录实际来源、范围、事实/规划/风格版本；不为了改版号重做无关章节。
4. 验收新快照是否承接章纲硬点和 F1 开章条件，记录验收证据。通过后仅激活一个当前包，同步入口与进度。
5. 原授权内继续开写；若 F1 来源或开章硬事实经定向回读仍无法确认，只停止依赖该事实的正文，列明所需证据。

**是否停止：**暂停受影响正文，直到重验通过；不需要把常规失效修订变成新的用户许可环节。若存在必须由用户决定的方向/授权冲突或无法补证的硬事实，再请求处理。

**依据：**U-I 61、67–78、88–90；D-C 24–27；D-H 21–34、40–47；D-Q 45。

**规则缺口：**未发现影响本情境裁决的缺口。规则明确要求内容与验收版本对应；“改名即升级”不是可用例外。技能提供人工核验规范，不能据此声称已有自动版本校验器实际拦截了该文件。

## 情境 2：第 1 章已初稿并润色，第 2 章仅初稿，两章均无 checker/主审，中断恢复，全部任务已授权

**应答：**“我会先核对两章正文和已有阶段证据。第 1 章从 checker 开始，第 2 章从润色开始；随后补齐修复复审、主审和接受实绩入账，继续完成已授权的两章范围。”

**动作序列：**

1. 核对实际正文、writer/polisher 报告及其输入输出版本、当前包有效性、未结项和两章依赖；不能只相信进度勾选。两章均未终审接受，不提前列为正式实绩。
2. 恢复记录写为：第 1 章“已润色，下一动作 checker”；第 2 章“已初稿，下一动作 polisher”。记录具体正文与报告位置/版本。若已完成阶段缺过程证据，应说明缺口并据当前文本补核必要项，不编造此前角色、报告或调用记录。
3. 对第 1 章当前润色稿执行 checker；有红色问题则定点修复，并检查修改对第 2 章初稿的影响。第 2 章在最新有效约束下润色，再执行 checker。已有初稿和有效润色证据不因恢复而机械重写。
4. 对两章需要修复的部分及跨章依赖复审，黄色项保留明确处理决定。改正文即登记新版本，不能继续引用受影响的旧通过结论。
5. 主 agent 复核各阶段证据、跨章事实链与候选变化，执行适用的卷末/跨卷审查或记明不适用理由；明确接受后才入账并消费当前包。
6. 分别记录本批完成与用户两章范围完成。确有仍在授权范围内的后续任务且闸门通过，继续执行；两章就是全部范围时，记录范围结束，不造空包。

**是否停止：**不因中断、已有两个不同阶段、或“写完一批”例行等待用户。缺 checker/主审表示需要继续完成阶段，不表示必须重新征求许可。只在真实未解决依赖或授权边界处暂停受影响动作。

**依据：**D-C 31–38；D-W 7–11、27–49、55–60；D-A 3–7、89–94；D-E 12、36；D-Q 31–45。

**规则缺口：**未发现恢复顺序的阻断缺口。技能没有指定所有混合阶段都使用唯一全局调度顺序；允许选择满足章节依赖的安排。上面的先后是本情境的一种合规序列，不是新增“必须逐章全部验收后才能碰下一章”的规则。

## 情境 3：两章终章四阶段完成，报告对应当前版本，状态已回写，用户要求不要续写

**应答：**“两章范围可以按有效证据办理结束，不需要为结束任务生成下一包。我会核对收尾所需证据，记录当前范围完成和无活动正文包，并遵守不要续写的要求。”

**动作序列：**

1. 核对给定四阶段记录确实对应现稿，以及必要修复复审、黄色项裁决和适用终章/卷末审查均已处理；情境未说明的适用审查不能自动写成通过。
2. 核对已接受实绩回写位置和引用版本。若当前包尚未标记 `consumed`，完成消费记录、保留历史报告引用，并移出可执行入口。
3. 分别登记：本批完成；若两章就是用户全部范围，则用户范围完成；下一批“不适用：用户要求停止且无下一批任务”；全书完结仅在全书授权目标和必要全书收束审查也有证据时成立。
4. 停止正文，不生成空下一包、不增加新事件或机械钩子。若发现本次交付内尚欠收尾审查，只补齐核验和必要问题处理，不能把“不要续写”解释成允许另起新章。

**是否停止：**是，在完成当前范围必要收尾后停止；这是遵守用户范围，不是流程受阻。下一包不是本批或用户范围完成的前提。

**依据：**U-I 90–92；U-Q 34、56；D-W 49、55–60；D-Q 15、40–45。

**规则缺口：**未发现。“末批完成”和“全书完结”的证据要求有明确区分，不能把题干中的终章一词单独当作全书审核证据。

## 情境 4：钥匙状态问题已修正文，但 checker 通过报告仍指向旧稿

**应答：**“旧 checker 报告只能证明其所审旧版本，不能给修订后的钥匙状态背书。我会登记新稿版本，对钥匙状态及受影响跨章依赖复审，再依据新证据主审。”

**动作序列：**

1. 对照修复前后正文和旧 checker 所审版本，定位钥匙的持有人、取出/收起/交接等实际被改状态及后续使用依赖。
2. 保留旧报告历史记录，将依赖被改内容的通过结论对新稿标为失效。历史初稿/润色报告仍可证明其原输入输出过程，不因此抹除所有阶段证据。
3. 对当前新版本和受影响跨章依赖复审，形成含正文定位、所审新版本、问题处置和结论的新证据；不能只修改旧报告的版本字段。
4. 如复审仍需改稿，继续“新版本 → 对应复审”。主 agent 据当前有效证据终审，接受后才回写钥匙实绩和放行依赖它的后续任务。

**是否停止：**暂停对新稿的“已通过/已接受”宣告及依赖该结论的入账或后续放行；继续局部复审工作，不重跑无关章节，也不默认从初稿阶段重来。

**依据：**D-C 24–27、38；D-W 35–37、41–49；D-A 65；D-Q 31–34。

**规则缺口：**未发现。报告失效按内容依赖和影响范围处理；“正文改过所以所有历史过程证据作废”也不符合当前规则。

## 情境 5：用户要两章可直接扩写，第 1 章有详纲，第 2 章只有标题

**应答：**“两章目录已有，但两章可直接扩写的任务尚未完成。第 2 章仍欠施工图；第 1 章还需按直接扩写质量门核验，不能只凭文件名或‘详纲’称呼计算通过。我会继续补足并审查第 2 章，保持两章总目标。”

**动作序列：**

1. 固定用户范围为两章，要求深度为“可直接扩写”，不将任务缩成“首章就绪”或“目录齐全”。
2. 如实登记三个维度：目录覆盖可记 2/2；结构规划和可直接扩写覆盖不得把只有标题的第 2 章计入。第 1 章只有在对应内容与审查证据核实后才能计为通过；若已核实，则可直接扩写覆盖为 1/2，否则写“第 1 章待核验，第 2 章未达到”，不凭称谓虚报 1/2。
3. 在现有授权和大纲范围内补第 2 章的目标、阻力、必要条件、场景节拍、转折、信息/关系变化、收束或钩子、技法落点、可写材料及适用连续性约束。保持上游条目形式，不代写正文或完整对白。
4. 审查两章的因果与接口，将每种覆盖的范围、缺口、版本、结论和证据写入进度；发现来源缺失且影响硬事实，定向补证或列为待定，不猜测。
5. 只有两章均满足请求深度及审查要求，才记录用户范围完成。纯规划交付不强制激活正文包；若同时需要交接开写，再按包验收要求处理。

**是否停止：**不能以“已完成”结束当前任务；应继续已授权的规划补足工作。第 2 章的正文开写门保持关闭。只有补证后仍无法解决的硬事实/方向问题才需要用户处理。

**依据：**U-I 7、39、47–55、84；U-P 34–36；U-Q 9、32–41；U-H 19、41。

**规则缺口：**未发现范围和成熟度边界缺口。详纲标签本身不证明质量门通过；上述保守计数是证据要求的运用，不是另设新的成熟度标准。

## 情境 6：草稿临时增加陆恒提前偷看交接单，因而早知柜台划痕；大纲要求看苏岚展示原件才知道

**应答：**“这段新增过去事件改变了已定的信息获得顺序，不能作为普通细节回写实绩。我会把它记为未接受偏移，驳回提前知情设定，修复为陆恒在苏岚展示原件后才获得相应信息，再检查受影响的推理和反应。”

**动作序列：**

1. 对照草稿、包硬点及对应章纲，定位两个相互冲突的知情路径：草稿的“提前偷看”与大纲的“展示原件后才知晓”。若执行包漏载这一硬点，定向补证并修正包的承接缺口，不能因包漏写就把草稿合理化。
2. 将新增偷看事件及提前知情列为未接受候选偏移，记录它对知情时点、推理和人物反应的影响。不能直接登记为 B 级自然状态变化，不能据此改正式基线或把后续规划改成接受既成事实。
3. 本情境已有明确规划约束且没有更改该约束的用户授权，默认裁决为“驳回该候选，修正文后复审”。删改提前知情的因果依赖，保留大纲已定的展示原件路径；不能再补造另一件过去事件来给早知划痕找理由。
4. checker 按硬点偏差记录阻断的连续性问题；主 agent 按实际影响判断是否涉及 C 级后续规划或 D 级卷目标/核心规则/关键动机/伏笔窗口。题干不足以证明上述全部结构影响，故不伪造具体 C/D 结论；这种分级不确定不影响“不接受、不入账、先修复”的明确决定。
5. 修正文后登记新版本，使受影响旧报告结论失效，复审该章及依赖提前知情的后续段落。只有符合硬约束的现稿经主审接受后，才把实际发生的信息获得时间与来源写入认知实绩；被驳回的“偷看”仅留在审查记录中。

**是否停止：**停止候选入账、接受宣告及依赖错误认知的后续正文；自主进行授权范围内的局部修复和复审。不能把用户的一般扩写授权解释为允许改动关键知情顺序。只有用户明确要求保留相冲突的新方向时，才需处理规划/授权变更。

**依据：**D-C 5、15–20、24–25；D-W 23、27–29、35–47；D-A 22、27–28、40、44、58–65；D-Q 24–26；U-I 13–18。

**规则缺口：**没有阻碍本情境主要裁决的缺口。A/B/C/D 是影响分级，红/黄/绿是问题严重度，现有文本没有为每一种“提前知情”建立唯一对应等级；这需要按影响证据裁决，不能假定所有提前知情都自动达到 D，也不能借分级尚未确定放行硬约束偏差。

## 汇总与验证限制

| 情境 | 直接决定 | 停止范围 | 原授权内下一动作 |
|---|---|---|---|
| 1 | 文件改名不能让 F0 快照适用于 F1 | 受影响正文开写 | 修订、重验、唯一激活后开写 |
| 2 | 两章都尚未接受；按各自下一阶段恢复 | 仅实际依赖阻塞，不例行等许可 | 第 1 章 checker；第 2 章润色；完成后续阶段 |
| 3 | 范围收尾不需要下一包 | 当前范围结束后停止正文 | 核验收尾证据、消费旧包、记录停点 |
| 4 | 旧稿通过不能背书新稿 | 新稿接受、入账及依赖放行 | 复审修改内容与跨章依赖 |
| 5 | 目录 2/2 不等于两章直接扩写完成 | 第 2 章正文开写 | 核验第 1 章、补足并审第 2 章 |
| 6 | 违规候选不回写正式实绩 | 错误知情依赖与入账 | 驳回候选、修稿、复审、主审后记合法实绩 |

当前阅读范围内，六项均有明确的主要处理依据，未发现必须修改源规则才能作出安全且连续决策的阻断缺口。混合阶段的具体调度、依赖影响范围和 C/D 等级仍需项目证据；报告明确保留这些未由情境给定的事实。

本报告证明的是**当前源规则下的边界推演可执行性**。它不证明真实小说已完成四阶段，不证明客户端已加载源技能，不证明自动拦截或持续状态系统已部署，也不评价真实小说文学效果。
