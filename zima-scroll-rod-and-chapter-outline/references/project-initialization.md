# 根据本书大纲初始化项目

本文件是项目配套资料、覆盖成熟度、包版本和更新顺序的统一规范。源 skill 保存生成与验收方法；本书人物、情节、设定、风格及具体路径写入小说项目，不回填源 skill，也不要求另造项目 skill。

## 1. 读大纲与确认交付范围

先读用户指定大纲及版本、项目权威输入和已有正文，记录用户要求的全范围、交付深度、当前批次及未完成范围。局部批次只是执行粒度；用户要全书详细章纲时，不能把目标缩成首批可写。沿用项目现有文件，缺失时才建立等价材料。

对配置、规划和状态中的关键结论标明来源性质，可按条目或明确分区标记：

| 标记 | 含义与使用边界 |
|------|----------------|
| 大纲已定 | 大纲或用户已明确的规划约束，记录来源位置；未来事件尚未发生 |
| 本轮设计 | 在授权设计空间内补出的候选安排，记录依据、影响范围和验收状态 |
| 待定 | 来源缺失、互相冲突或需要用户决定；阻断项解决前不激活相关正文包 |
| 已接受正文实绩 | 已完成审查、必要修复复审并由主审接受的正文证据，记录章节与版本 |

规划输出不能直接登记为已发生事实；大纲已定的开篇条件可作为“初始状态”，仍注明大纲来源。未审正文只记候选实绩；接管既有正文先核实其接受状态，不把新规划当理由覆盖旧文。

## 2. 生成本书配置

从上述输入抽取，而不是套用上一本书的答案：

- 本书标识、题材与读者体验、用户总范围与要求深度。
- POV/叙述距离、时间与信息边界。
- 表达配置与风格依据：用户要求、已接受样章或现有正文的位置和版本；无样章时给出有依据的暂定配置，不伪称已匹配。
- 硬约束：不可改的情节、人物动机、世界规则、连续性及用户红线。
- 可设计空间、待定项及其阻断范围。
- 权威材料、规划、状态、审查、包和当前入口的实际路径与版本。

表达配置描述本书需要的叙述、对白、信息密度、节奏和禁区。下游默认按 `human-writing` 的小说适配润色，并服从本书配置；上游只交表达依据和约束，不另写一套正文，也不以通用去 AI 痕迹规则覆盖小说声音。

## 3. 按适用性生成配套资料

下面规定的是信息职责，不是必须拆出的文件数量；可以合并进已有文档，以清晰标题、锚点和版本保持可查。

| 类别 | 应有材料 | 生成条件 |
|------|----------|----------|
| 通用必需 | 本书配置、来源与约束、用户总目标/当前批次/覆盖成熟度、按请求深度生成的卷段与章纲、初始状态或已接受正文实绩、风险/待定、当前入口与进度；开写范围另需分章技法和可写材料 | 每本书都需能找到相应职责；纯规划任务不强行激活正文包 |
| 按内容需要 | 伏笔回收、时间线、角色认知与信息来源、关键道具、术语或系统规则、人物关系与资源等状态表 | 内容确实涉及相应连续性时生成；普通小说不强加系统或术语体系 |
| 按阶段需要 | 卷级接口、规划审查、正文批审/卷末审查、跨卷串联审查、本批输入包和当前执行包 | 随规划、首批开写、续批、卷末或跨卷阶段生成；无卷划分可用实际叙事段接口 |

交接清单逐项写“必需 / 条件适用 / 不适用及理由”。不适用不是缺项，不生成空壳来凑清单；条件已触发却无材料才是缺口。规划审查可以在零正文时完成，不能冒称正文卷末审查已通过。

## 4. 审查规划与覆盖成熟度

对用户全范围分别记录三个维度，允许用一张范围表合并表达：

| 维度 | 可以证明什么 | 不能替代什么 |
|------|--------------|--------------|
| 章纲目录覆盖 | 章节编号、标题或功能位置齐全 | 结构审查和逐章扩写深度 |
| 结构规划覆盖 | 因果、起终状态、冲突与回报、必要接口有设计并已审 | 每章可直接落笔的施工图 |
| 可直接扩写覆盖 | 每章有目标、阻力、必要条件、场景节拍、信息/关系变化、技法落点、可写材料及适用的连续性约束 | 正文已写、正文审查或全书完成 |

每个维度记录实际覆盖范围、缺口、版本、审查结论与证据。只给“冲突升级”等功能标签不算可直接扩写。若用户只要目录或简纲，按该深度交付并如实标明；若要全范围施工图，就继续补足未完成范围，不能用目录齐全或首批就绪代替完成。

## 5. 输入包与执行包

**本批输入包是规划依据**：章节范围、规划来源、分章施工图、技法/可写材料、本书表达配置及适用的连续性设计。可引用已版本化材料，不必重复全文。

**当前执行包是最新事实校准快照**：引用对应输入包，带入开写前已接受正文实绩或初始状态，明确本批目标与执行模式、分章施工卡、硬门/软门、回读触发器、写后硬点覆盖表和反馈格式。输入包存在并不自动意味着执行包可用。

两类包共用以下元数据；Markdown 表格或页首字段即可，不强制 JSON。合为一份文件时也应区分两种职责及版本引用。

| 字段 | 要求 |
|------|------|
| 本书标识 | 稳定标识，防止跨书混用 |
| 包 ID / 版本 / 包类型 | 可唯一定位本次输入或执行快照 |
| 章节范围 | 明确本包覆盖范围，并引用用户总范围记录 |
| 规划来源版本 | 具体大纲、卷章纲等路径与版本 |
| 事实基线版本 | 已接受正文/状态的版本；零正文写初始状态版本并注明“无已接受正文” |
| 风格版本 | 本书表达配置的位置与版本 |
| 状态 | `draft` / `active` / `consumed` / `invalidated` |
| 生成者 / 验收证据 | 谁生成、谁验收，审查记录位置、结论及必要修复复审证据 |

状态转换：新建或修订先为 `draft`，初次验收未通过仍为 `draft`；验收通过后登记 `active`；被执行且本批终审、实绩入账完成后为 `consumed`；已启用包因依赖版本改变而过期、被替换或复查不通过时为 `invalidated`。保留历史版本和失效原因，不静默覆盖。

同一本书的当前正文入口只指向一份 `active` 当前执行包，所引用的输入包不能成为第二个开写入口。启用新版本时同时撤销旧入口；核对本书、章节范围、来源/事实/风格版本和验收证据，不能只检查文件存在或一个 `active` 字样。

## 6. 零正文首批启动

无正文时：完成本书配置和适用配套资料 → 按用户要求审查规划并记录覆盖成熟度 → 从已审规划与初始状态生成首批输入包、`draft` 执行包 → 验收版本、范围、连续性和阻断项 → 登记唯一 `active` 首批执行包。

首批不需要上一批报告或不存在的正文卷末/跨卷报告；验收证据来自本轮规划审查和初始状态核对。首批可开写只说明该范围通过开写门，不改变用户全范围规划仍未完成的状态。

## 7. 批后更新与下一入口

续批顺序固定为：写作 → 润色 → 审查 → 修复与复审 → 主审及必要跨卷审查 → 已接受正文实绩入账 → 修订受影响的后续规划 → 下一包验收并激活。没有修复项时注明无需修复；待审正文不提前写成基线。

按影响范围更新状态、伏笔/接口、表达配置和规划；相关旧包失效，重建受影响范围的快照，不无故重做无关章节。下一包有阻断项时保留 `draft`，进度写明阻塞及下一入口；没有下一批任务时不造空包，当前入口注明无活动正文包及停点原因。

进度与交接必须分别说明“本批完成”“用户要求范围完成”“下一批可开工”“全书完结”，每项给出范围、证据或未完成原因。结束当前范围不自动等于全书完结；全书完结需要全书正文和适用终审证据。
