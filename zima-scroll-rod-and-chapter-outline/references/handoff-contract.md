# 与正文写作的交接契约

`zima-scroll-rod-and-chapter-outline` 是上游，`zima-write-web-story` 是下游。二者不合并，也不互相全文读取。

## 上游必须交付

交给正文写作前，至少准备：

| 内容 | 作用 |
|------|------|
| 当前卷纲 | 固定卷级目标、阻力、高潮、代价、回报点 |
| 本批章纲 | 固定章节范围、目标、冲突、必要条件、钩子 |
| 本批输入包 | 集中给出章节范围、事实基线、分章施工图和风险 |
| 每章技法包 | 指明正文扩写时每章 1-3 个技法及落地点 |
| 每章可写材料层 | 提供物象、动作、对白遮掩、误读/错认、题材细节和节奏提示，避免只有功能标签 |
| 伏笔/回收表 | 防止伏笔遗失、强行回收或窗口错位 |
| 人物状态 | 保持动机、关系、资源、伤势、认知连续 |
| 术语认知规划 | 标明正式命名窗口、首次知晓角色、允许/禁止表达 |
| 角色认知路径 | 标明姓名、身份、关系、地点、规则等信息的来源 |
| 关键道具状态路径 | 标明道具章初、章中、章末状态和结构功能 |
| 卷级接口卡 | 承接前卷并向下一卷输出连续状态 |
| 单卷/跨卷审查报告 | 给下游理解已知偏差、风险和修复项 |
| 下一批风险 | 提醒正文阶段重点避坑 |

## 既有正文接管

如果当前卷已有正文，上游先建立正文实绩基线。已写正文优先于旧规划，除非存在必须暂停的红色硬伤。

实绩基线至少包含：已写范围与关键剧情、人物/关系/伤势/资源状态、关键道具状态、术语与角色认知实绩、伏笔库存，以及对后续章纲的 C/D 级影响。

## 下游只做存在性判断

`zima-write-web-story` 只判断这些材料是否存在、是否足够支撑正文写作。缺失时提醒补齐上游产物，而不是加载本 skill 全文临时补课。

## 允许下游微调

正文阶段可以微调：

- 场景切入顺序。
- 对话节奏。
- 道具细节。
- 可写材料层的具体落笔方式。
- 单章钩子表达。
- 技法落地方式。

正文阶段不能随意更改：

- 卷级目标。
- 人物关键动机。
- 重大伏笔回收窗口。
- 世界观硬规则。
- 已通过审查的跨卷状态。

需要更改这些内容时，回到本 skill 更新卷纲、章纲或审查报告。

## 下游反馈回流

下游反馈按 A/B/C/D 分级：A 只留档；B 更新状态表、接口卡或风险；C 修订下一批章纲、输入包、材料层、认知路径或伏笔窗口；D 暂停正文，先修卷纲、核心设定或旧文红色问题。

## 当前执行包生成

每批正文完成后，主 agent 必须先完成下游终审和 A/B/C/D 分级，再生成下一批当前执行包。执行包至少包含当前事实、本批目标与模式、分章施工卡、硬门、软门、回读触发器、写后硬点覆盖表和反馈格式。

生成后必须登记到项目当前入口和进度文件，状态标为 `active`。未登记 active 当前执行包时，下游不得进入下一批正文。
