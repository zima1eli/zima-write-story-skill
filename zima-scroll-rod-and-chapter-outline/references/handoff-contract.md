# 与正文写作的交接契约

`zima-scroll-rod-and-chapter-outline` 是上游，`zima-write-web-story` 是下游。二者不合并，也不互相全文读取。

项目初始化、包元数据/生命周期、首批与续批顺序以 `project-initialization.md` 为统一规范。交接以下信息职责，可合并文件；逐项登记适用性和实际路径。

## 通用必需

| 内容 | 作用 |
|------|------|
| 本书配置与表达依据 | 标明本书、用户范围/深度、POV、风格版本、硬约束、设计空间与待定项 |
| 当前卷/段纲 | 固定当前叙事段目标、阻力、高潮、代价、回报点；不强制分卷 |
| 本批章纲 | 固定章节范围、目标、冲突、必要条件、钩子 |
| 本批输入包 | 集中给出版本化规划依据、分章施工图和风险 |
| 当前执行包 | 给出最新事实校准快照，核验后由唯一当前入口登记 `active` |
| 每章技法包 | 提供足以支撑本章的技法及落地点，通常 1–3 项；可复用已验收方法，不为凑数增加 |
| 每章可写材料层 | 提供物象、动作、对白遮掩、误读/错认、题材细节和节奏提示，避免只有功能标签 |
| 初始状态或已接受正文实绩 | 给出开写状态、来源性质和版本，不把未来规划登记为事实 |
| 规划审查、成熟度与进度 | 区分目录/结构/可直接扩写覆盖，保留用户全范围目标和未完成范围 |
| 风险/待定与验收证据 | 明确当前阻断项、修复结论和下一入口 |

## 条件适用与不适用

| 条件 | 所需信息 |
|------|----------|
| 存在相关连续性 | 伏笔回收、人物关系/资源/伤势、角色认知、关键道具、时间线等状态与设计 |
| 存在专门术语或系统规则 | 命名窗口、首次知晓与信息来源、允许/禁止表达 |
| 分卷且有卷间依赖 | 卷级接口、必要跨卷审查与承接风险 |
| 已有正文进入对应阶段 | 实际完成的批次、正文卷末或跨卷审查报告及修复复审记录 |

不适用项记录理由即可；零正文首批使用规划审查与初始状态，不要求上一批报告。审查对象必须明确，规划审查不能替代正文卷末审查。

## 既有正文接管

如果当前卷已有正文，上游核实其接受状态后建立正文实绩基线，未审内容单列。已接受正文优先于旧规划，红色硬伤进入暂停与修复流程。

实绩基线包含已接受范围、正文版本与关键剧情、适用的连续性状态，以及对后续规划的 C/D 级影响。

## 下游验收

`zima-write-web-story` 核对本书、范围、规划/事实/风格版本、适用材料、验收证据与唯一 `active` 入口，判断是否足够支撑本批。缺项、待定阻断或版本不一致时退回具体问题，不只看文件是否存在，也不加载本 skill 全文补课。上游交本书表达配置，下游默认以 `human-writing` 小说适配润色正文。

## 允许下游微调

正文阶段可以微调：

- 场景切入顺序。
- 对话节奏。
- 不改变结构功能和连续性的道具描写细节。
- 可写材料层的具体落笔方式。
- 单章钩子表达。
- 技法落地方式。

正文阶段不能随意更改：

- 卷级目标。
- 人物关键动机。
- 重大伏笔回收窗口。
- 世界观硬规则。
- 已通过审查的跨卷状态。

需要更改这些内容时，回到本 skill 更新卷纲、章纲或审查报告。

## 下游反馈回流

下游反馈按 A/B/C/D 分级：A 只留档；B 更新状态表、接口卡或风险；C 修订下一批章纲、输入包、材料层、认知路径或伏笔窗口；D 暂停正文，先修卷纲、核心设定或旧文红色问题。

## 当前执行包生成

按 `project-initialization.md` 区分零正文首批与后续批次。主 agent 在相应验收完成后登记唯一 `active` 执行包；旧包的失效/消耗、影响范围与完成状态同步进度。未通过验收的包保持 `draft`，不得开写；无下一批时不生成包。
