# 卷纲、章纲与技法包工作流

## 0. 先建立当前事实

- 根据大纲初始化本书时，先按 `project-initialization.md` 建配置、判定资料适用性并记录用户全范围/深度；以下模板按需要生成，不要求每项独立成文件。
- 普通续作先读当前入口、当前执行包、最近进度和与本批有关的上游产物，不默认通读全项目。
- 如果已有正文，以已接受正文和可核查审查报告建立实绩基线；未审内容单列，旧计划与正文冲突时优先修订后续规划。
- 新项目、用户要求全范围规划、新卷、跨卷、卷末或偏离风险触发相应扩大回读，不能因批次粒度省掉用户要求的范围。
- 详细接管、反馈和执行包流程见 `planning-harness.md`。

## 1. 大纲诊断

先从大纲与项目证据回答，按“大纲已定 / 本轮设计 / 待定 / 已接受正文实绩”标明性质：

- 类型组合是什么？
- 主角欲望和错误信念是什么？
- 当前卷起点、终点、高潮、代价和中程回报点是什么？
- 长线谜团、人物弧和世界观规则在本卷推进到哪里？
- 当前材料哪里可能平、拖、断逻辑、钩子弱或伏笔空降？
- 本书 POV、表达依据、硬约束与设计空间是什么？用户要求的是目录、结构规划还是逐章可直接扩写？

诊断要短，用来决定结构方案，不写成正文赏析。

## 2. 卷级结构选择

按故事需要选择一到三种策略：

- 高潮逆推：先定本卷高潮和代价，再反推铺垫。
- 计划-意外循环：目标、计划、意外、目标升级。
- 冲突阶梯：外部障碍、内部矛盾、代价升级。
- 三层期待：章末钩子、本卷回报、全书谜团。
- 平淡期留人：倒计时、支线交叉、信息差、状态转换。
- 伏笔网：先定目的地，再安排埋设、加深、误导和回收窗口。

## 3. 卷纲模板

字段随题材与内容适用性取舍，无卷划分时按叙事段使用。这里的起终状态和伏笔安排是规划，不自动成为正文实绩。

```markdown
# 第X卷 · 卷名

## 卷级定位
- 类型功能：
- 本卷主题：
- 起点状态：
- 终点状态：
- 本卷核心阻力：
- 本卷中程回报点：
- 本卷宏观谜团推进：

## 叙事弧分段
| 段 | 章节 | 功能 | 主要冲突 | 情绪走势 | 期待感设计 |
|----|------|------|----------|----------|------------|

## 卷级技法包
| 技法 | 来源页面 | 用在何处 | 具体落地 |
|------|----------|----------|----------|

## 伏笔与回收
| 伏笔/问题 | 埋设章 | 加深章 | 回收/阶段答案 | 作用 |
|-----------|--------|--------|----------------|------|

## 章纲目录
| 章 | 章名/临时名 | 本章任务 | 冲突升级 | 情绪线 | 钩子类型 | 正文扩写技法 |
|----|-------------|----------|----------|--------|----------|--------------|

## 风险与修正
- 逻辑风险：
- 节奏风险：
- 人物动机风险：
- 红线/题材风险：
- 下一步正文写作注意：
```

## 4. 章纲模板

此模板用于可直接扩写深度；目录表不等于已完成所有章的施工图。连续性字段仅在相关内容出现时填写并给出信息来源；场景节拍按本章功能取舍，终章允许安静闭合，不为模板新造悬念或下一章。

```markdown
# 第XXX章 · 临时章名

## 章纲卡
- 浓缩句：
- 关键词：
- POV/主视角：
- 本章目标：
- 核心冲突：
- 必要条件：
- 情绪线：
- 信息增量：
- 读者期待：

## 可写材料层
- 物象/环境：
- 动作与道具：
- 对白遮掩或信息差：
- 误读/错认：
- 题材细节与节奏提示：

## 场景节拍
1. 开场切入：
2. 阻力出现：
3. 计划/应对：
4. 意外或反证：
5. 情绪/关系变化：
6. 小高潮：
7. 章末牵引或收束：

## 正文扩写技法
| 技法 | 选择原因 | 落地点 | 避免事项 |
|------|----------|--------|----------|

## 伏笔与连续性
- 承接上一章：
- 本章埋设：
- 本章回收：
- 推给下一章：
- 术语认知路径：
- 角色认知路径：
- 关键道具章初/章末状态：

## 自检
- 是否有“是什么/为什么”因果配对：
- 情绪节拍是否符合本章功能（上升、缓降、余波或收束）：
- 是否推进信息或关系：
- 牵引或收束是否服务核心阻力且有铺垫：
```

如果用户只要简版章纲，可压缩表达，保留浓缩句、情绪线、必要条件、场景节拍、钩子、技法及适用的硬连续性条目，并如实记录成熟度。用户要求全范围详细章纲时，不能以当前批次完整或目录覆盖代替全范围完成。

## 5. 优化已有卷纲/章纲

先诊断再补强，不默认推翻重写。

| 问题 | 修法 |
|------|------|
| 流水账 | 改成关键帧：任务、阻力、情绪变化、钩子 |
| 平淡 | 增加信息差、倒计时、代价、价值错位或连锁反应 |
| 拖水 | 合并无增量章节，过场用留白或状态转换 |
| 逻辑断裂 | 做“是什么/为什么”配对，补人物动机和前置条件 |
| 钩子弱 | 换成服务阻力的语言、道具、情节或思维钩子 |
| 技法堆名词 | 每个技法落到章节的动作、信息、情绪或道具 |
| 伏笔空降 | 先定目的地，再安排埋设、加深、误导、回收 |

优化结果按影响范围同步后续章纲与输入包；相关旧执行包失效，新快照经验收后再激活。具体版本、状态与完成口径遵守 `project-initialization.md`，不能让下游继续读取过期入口。
