# 上游规划 harness

第一性原则：上游把未来正文的不确定性压缩成可执行交接包；下游执行、记录正文实绩并反馈。规划必须服从当前事实，不能用过期计划覆盖已落盘正文。

## 适用范围

- 新建或优化卷纲、章纲与章节技法包。
- 根据既有正文接管项目状态。
- 生成卷级接口卡、本批输入包和下一批当前执行包。
- 做单卷或跨卷接口审查。
- 吸收下游反馈，修订下一批或下一卷规划。

## 0. 既有正文接管

当前卷已有正文时，先把正文视为事实基线：读取已写章节、当前卷纲/章纲、当前入口、项目进度和已有审查报告；记录已写范围、关键剧情、人物与关系、伤势/资源、关键道具、术语与角色认知、伏笔库存和风险。

旧计划与正文实绩不一致时：

| 级别 | 处理 |
|------|------|
| A | 只记录，不改规划 |
| B | 更新状态表、接口卡或风险记录 |
| C | 修订下一批章纲、输入包、材料层、认知路径或伏笔窗口 |
| D | 暂停正文，先修卷纲、核心设定或旧文红色问题 |

优先修订后续规划；只有 D 级硬伤才建议回修已写正文。

## 1. 单卷规划

卷纲必须回答：本卷为什么非读不可；起点、终点、高潮、代价和回报点是什么；核心阻力如何升级；人物的核心信念或行动逻辑如何被事件持续碰撞；伏笔、术语、规则和身份信息如何分配；卷末给下一卷留下什么状态接口。

## 2. 章纲施工图

每章至少包含：目标、冲突、必要条件、转折、钩子、1—3 个技法及落点、可写材料层、术语认知路径、角色认知路径、关键道具状态和伏笔窗口。

可写材料层只写物象、动作、对白遮掩、误读/错认、题材细节和节奏提示等短条目；不代写正文，不给完整对白。

## 5. 跨卷接口审查

对照前卷接口卡、当前卷规划和必要正文实绩，检查人物/关系/伤势/资源承接、道具位置与状态、术语和角色首次知晓、伏笔窗口、主线谜团节奏以及卷末对下一卷的输出。审查目标是保证接口连续，不是重写整卷。

## 6. 下游反馈吸收

按 A/B/C/D 处理下游反馈；同类黄色问题连续出现两次以上，至少按 C 级处理，说明上游施工图存在缺口。

## 7. 下一批当前执行包

主 agent 只在上一批已完成写作、润色、校对和终审，且状态表、伏笔表、项目进度与 A/B/C/D 反馈均已处理后，生成下一份当前执行包。

执行包至少包含当前事实、本批目标与执行模式、分章施工卡、硬门、软门、回读触发器、写后硬点覆盖表和反馈格式。生成后登记到项目当前入口与进度文件，并标记 `active`；在此之前，下一批正文不得开写。
